# Video Comparison Study

A static website for a forced-choice video user study, built for GitHub Pages.

Each video already contains several versions of the same clip side by side, labeled **A, B, C**. The rater watches the video and picks the version that is **most semantically aligned with the leftmost (GT) video**. The rater:

1. Enters a participant ID (or gets one from the link, e.g. `?id=P017` or `?PROLIFIC_PID=...`) and gives consent.
2. Watches each video. The order is different for each rater.
3. Picks A, B or C once the video has finished, by clicking a button or pressing A/B/C or 1/2/3.

Answers go straight into a Google Sheet that only you can see. The Sheet also holds the **mapping** (which method is A, B, C in each video), so the site and the public repo never reveal it.

Live site: https://lido91.github.io/video-rating-study/

```
index.html, style.css, app.js   the site
config.js                       your study settings (title, instructions, choices, question, Sheet URL)
videos/                         your video files
videos.js                       list of videos, generated by make_video_list.py
make_video_list.py              scans videos/, writes videos.js and mapping_template.csv
apps-script/Code.gs             Google Sheet backend (paste into Apps Script)
```

---

## 1. Add your videos

Copy your videos into `videos/`. Subfolders are fine, e.g. `videos/set1/clip01.mp4`. Then run:

```bash
python3 make_video_list.py
```

This writes:
- `videos.js`: the list of videos the site shows.
- `mapping_template.csv`: one row per video with empty A, B, C columns, for step 2. It is git-ignored, so your mapping never ends up in the public repo.

It also warns you about:
- **Files over 100 MB.** GitHub rejects these. Keep the whole site under about 1 GB.
- **Codecs browsers can't play.** H.264 MP4, VP9 WebM and AV1 work. HEVC/H.265 only plays in Safari. ProRes, raw YUV and MPEG-4 Part 2 don't play in browsers. (This check needs `ffprobe`, which comes with ffmpeg.)

> **Reduce position bias.** People tend to favor one position, often the left one. When you make the videos, vary which method is in A, B and C from video to video, ideally so each method appears in each position equally often. The Summary's position check shows whether raters favored a position.

Each video's ID in the results is its path inside `videos/`, e.g. `set1/clip01.mp4`. Raters see the video at its own size, scaled down only if it doesn't fit the screen.

## 2. Set up the Google Sheet

1. Create a new Google Sheet, e.g. "Video study results".
2. Open **Extensions → Apps Script**. Delete the sample code, paste in all of `apps-script/Code.gs`, and save.
3. Choose `setup` in the function dropdown and click **Run**. Approve the permissions prompt. This creates the **Ratings**, **Mapping** and **Summary** tabs.
4. Click **Deploy → New deployment**. Under the gear icon choose **Web app**, then set:
   - Execute as: **Me**
   - Who has access: **Anyone**
5. Click **Deploy** and copy the **Web app URL** (it ends in `/exec`).
6. Paste the URL into `config.js`:
   ```js
   scriptUrl: "https://script.google.com/macros/s/AKfy.../exec",
   ```
7. Fill in the **Mapping** tab: one row per video, with the method shown as A, B and C:

   | video_id | A | B | C |
   |---|---|---|---|
   | clip01.mp4 | ours | baseline1 | baseline2 |
   | clip02.mp4 | baseline2 | ours | baseline1 |

   You can copy the rows from `mapping_template.csv`; the `.mp4` extension may be left out. If every video uses the same order, one row with `*` as the video_id is enough. You can fill this in before or after collecting answers, and the Summary updates as soon as you edit it.

To check it worked, open the web app URL in your browser. You should see `{"ok":true,"message":"Video rating endpoint is running."}`.

> **University Google accounts** (such as @ou.edu) sometimes don't offer the **Anyone** option. If you only see "Anyone within OU", raters outside OU will get an error. In that case, create the Sheet with a personal Gmail account instead.

> **If you edit Code.gs later**, go to **Deploy → Manage deployments**, click the pencil icon, set **Version → New version**, and click **Deploy**. The URL stays the same. Saving the file alone does not update the live web app.

## 3. Try it on your computer

```bash
python3 -m http.server 8000
```

Open http://localhost:8000/?id=test1&reset. Use `?reset` to forget this browser's progress so you can run through again. Delete your test rows from the Sheet before the real study starts.

If `scriptUrl` is empty, the site runs in **demo mode**. Answers stay in the browser, and you can download them as CSV at the end. This is useful for piloting.

## 4. Publish updates to GitHub Pages

This folder is connected to https://github.com/Lido91/video-rating-study, and Pages serves the `main` branch. After changing videos or settings:

```bash
git add -A
git commit -m "Add videos"
git push
```

The site updates about a minute later. Send each rater their own link: `https://lido91.github.io/video-rating-study/?id=P001`.

> **The repo is public, so the videos are too.** Anyone can download the files in it. Answers and the mapping are not in the repo; they live only in your Sheet. Don't use Git LFS for the videos, because GitHub Pages doesn't serve LFS files.

## 5. Your data

**Ratings** tab: one row per rater × video × question. It is never overwritten.

| column | meaning |
|---|---|
| `timestamp` | when the answer reached the Sheet |
| `rater_id`, `session_id` | who answered (the session ID changes if they start over on a new device) |
| `video_id` | the video, e.g. `clip01.mp4` |
| `choice` | the version picked: `A`, `B` or `C` |
| `options` | the choices offered, e.g. `A\|B\|C` |
| `trial_index` | the video's position in this rater's order (for order-effect checks) |
| `plays` | how many times they played the video |
| `stalls` | buffering interruptions (should be 0, because videos are fully downloaded before playing) |
| `video_seconds` | video length |
| `response_ms` | time from the end of the video to clicking Next |
| `note` | `playback_error` if the video couldn't play on their device (choice left blank) |
| `screen` | screen resolution in CSS pixels |

**Summary** tab: rebuilt every time an answer arrives or the Mapping tab changes. You can also use **Video ratings → Refresh summary** in the Sheet menu. Don't edit it by hand, because your changes will be overwritten. It has three tables:

1. **Preference by method** (needs the Mapping tab): how often each method was chosen, its preference rate, a 95% confidence interval (Wilson), and the chance level (33.3% with 3 choices). If the CI's lower bound is above chance, raters preferred that method more often than chance.
2. **Position check**: how often A, B and C were chosen. This should be close to chance unless one position always holds the best method.
3. **Per video**: for each video, how many raters picked A, B and C, the mapping, and the votes per method.

To analyze in Python, download the Ratings and Mapping tabs with **File → Download → CSV**, then run the code below. It assumes the Mapping tab has one row per video, using the full file name.

```python
import pandas as pd
df = pd.read_csv("ratings.csv")
df = df[df.note.isna()]
mapping = pd.read_csv("mapping.csv").melt(id_vars="video_id", var_name="choice", value_name="method")
df = df.merge(mapping, on=["video_id", "choice"])
df.method.value_counts(normalize=True)       # preference rate per method
pd.crosstab(df.video_id, df.method)          # votes per video
```

## Settings (config.js)

| setting | default | |
|---|---|---|
| `studyId` | `video-study-v1` | Change it for a new round; returning raters will then start fresh |
| `choices` | `["A", "B", "C"]` | The labels inside your videos, in button order. Use `["A", "B", "C", "D"]` for 4 versions |
| `questions` | "Which one — A, B or C — is most semantically aligned with the leftmost video?" | Add more objects to ask several things per video, e.g. `{ id: "sync", text: "Which has the best lip sync?" }` |
| `randomizeOrder` | `true` | Each rater gets their own order of videos, which stays the same if they reload |
| `requireFullWatch` | `true` | Answering unlocks only after the video has finished |
| `maxPlays` | `0` | How many times a video may be played (0 = unlimited, 1 = no replay). The actual number is recorded in `plays` either way |
| `askRaterId` | `true` | `false` = assign a random anonymous ID |
| `consent` | text | `""` = no consent checkbox |
| `completionCode` | `""` | Shown at the end, e.g. for Prolific or MTurk |

## Good to know

- **Saving is reliable.** Each answer is sent right away. If the connection drops, it is kept in the browser and re-sent later, and the Sheet ignores duplicates. A rater who closes the tab and returns with the same ID continues where they stopped.
- **Interrupted playback.** If the browser pauses a video midway (for example, the rater switches tabs), the button changes to "Play from start", and that interrupted play doesn't count against their limit.
- **The endpoint is open.** Anyone who finds the Sheet URL could submit rows. The script checks every value (for example, that the choice was one of the options offered), but you should keep only rows from the participant IDs you handed out.
- **Best on a computer.** Three versions side by side are small on a phone. The page still works there.
- Player controls and the right-click menu are disabled, so raters can't seek or change the speed.
