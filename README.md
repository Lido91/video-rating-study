# Video Comparison Study

A static website for a forced-choice video user study, built for GitHub Pages.

Each round shows several versions of the same clip side by side: your method and the baselines. They are labeled only **A, B, C, D**, and the rater picks the one that looks **most natural**. The rater:

1. Enters a participant ID (or gets one from the link, e.g. `?id=P017` or `?PROLIFIC_PID=...`) and gives consent.
2. Plays each round; all versions play together, in sync.
3. Picks a video once they have finished playing, by clicking it, its letter, or pressing a key (A–D or 1–4).

Methods are **blind and shuffled**: which method appears as A, B, C or D is randomized in every round, and the order of rounds is different for each rater. Answers go straight into a Google Sheet that only you can see.

Live site: https://lido91.github.io/video-rating-study/

```
index.html, style.css, app.js   the site
config.js                       your study settings (title, instructions, question, Sheet URL)
videos/<method>/...             your videos, one folder per method
videos.js                       list of rounds, generated by make_video_list.py
make_video_list.py              scans videos/ and writes videos.js
apps-script/Code.gs             Google Sheet backend (paste into Apps Script)
```

---

## 1. Add your videos

Make one folder per method inside `videos/`, and give the same file name to every version of a clip:

```
videos/
  ours/        001.mp4  002.mp4  003.mp4 ...
  baseline1/   001.mp4  002.mp4  003.mp4 ...
  baseline2/   001.mp4  002.mp4  003.mp4 ...
  baseline3/   001.mp4  002.mp4  003.mp4 ...
```

Folder names are the method names you'll see in the results; raters never see them. Files with the same name (ignoring the extension) become one round. Then run:

```bash
python3 make_video_list.py
```

The script writes `videos.js` and warns you about:
- **A clip that's missing in some method.** That round is skipped.
- **Versions of a clip with different lengths.** The round ends when the longest one finishes.
- **Files over 100 MB.** GitHub rejects these. Keep the whole site under about 1 GB.
- **Codecs browsers can't play.** H.264 MP4, VP9 WebM and AV1 work. HEVC/H.265 only plays in Safari. ProRes, raw YUV and MPEG-4 Part 2 don't play in browsers. (The codec and length checks need `ffprobe`, which comes with ffmpeg.)

> **Encode every method the same way.** If you need to convert files to H.264, use identical settings for all methods so compression doesn't favor one of them, for example `ffmpeg -i in.mov -c:v libx264 -crf 12 -preset slow -pix_fmt yuv420p out.mp4`.

## 2. Set up the Google Sheet

1. Create a new Google Sheet, e.g. "Video study results".
2. Open **Extensions → Apps Script**. Delete the sample code, paste in all of `apps-script/Code.gs`, and save.
3. Choose `setup` in the function dropdown and click **Run**. Approve the permissions prompt. This creates the **Ratings** and **Summary** tabs.
4. Click **Deploy → New deployment**. Under the gear icon choose **Web app**, then set:
   - Execute as: **Me**
   - Who has access: **Anyone**
5. Click **Deploy** and copy the **Web app URL** (it ends in `/exec`).
6. Paste the URL into `config.js`:
   ```js
   scriptUrl: "https://script.google.com/macros/s/AKfy.../exec",
   ```

To check it worked, open the web app URL in your browser. You should see `{"ok":true,"message":"Video rating endpoint is running."}`.

> **University Google accounts** (such as @ou.edu) sometimes don't offer the **Anyone** option. If you only see "Anyone within OU", raters outside OU will get an error. In that case, create the Sheet with a personal Gmail account instead.

> **If you edit Code.gs later**, go to **Deploy → Manage deployments**, click the pencil icon, set **Version → New version**, and click **Deploy**. The URL stays the same. Saving the file alone does not update the live web app.

## 3. Try it on your computer

```bash
python3 -m http.server 8000
```

Open http://localhost:8000/?id=test1&reset. Use `?reset` to forget this browser's progress so you can run through again. Delete your test rows from the Sheet before the real study starts.

If `scriptUrl` is empty, the site runs in **demo mode**. Answers stay in the browser, and you can download them as CSV at the end. This is useful for piloting.

## 4. Publish updates to GitHub Pages

This folder is already connected to https://github.com/Lido91/video-rating-study, and Pages serves the `main` branch. After changing videos or settings:

```bash
git add -A
git commit -m "Add videos"
git push
```

The site updates about a minute later. Send each rater their own link: `https://lido91.github.io/video-rating-study/?id=P001`.

> **The repo is public, so the videos are too.** Anyone can download the files in it. Answers are not in the repo; they live only in your Sheet. Don't use Git LFS for the videos, because GitHub Pages doesn't serve LFS files.

## 5. Your data

**Ratings** tab: one row per rater × round × question. It is never overwritten.

| column | meaning |
|---|---|
| `timestamp` | when the answer reached the Sheet |
| `rater_id`, `session_id` | who answered (the session ID changes if they start over on a new device) |
| `sample_id` | the clip, e.g. `001` |
| `choice` | the **method** the rater picked, e.g. `ours` |
| `choice_position` | where that video was shown (A = left-most / top-left) |
| `methods_shown` | the methods in positions A, B, C, D, separated by `\|` |
| `trial_index` | the round's position in this rater's order (for order-effect checks) |
| `plays` | how many times they played the round |
| `stalls` | buffering interruptions (should be 0, because clips are fully downloaded before playing) |
| `response_ms` | time from the end of the videos to clicking Next |
| `note` | `playback_error` if a video couldn't play on their device (choice left blank) |
| `screen` | screen resolution in CSS pixels |

**Summary** tab: rebuilt every time an answer arrives. You can also use **Video ratings → Refresh summary** in the Sheet menu. Don't edit it by hand, because your changes will be overwritten. It has three tables:

1. **Preference by method**: for each method, how often it was chosen, its preference rate, a 95% confidence interval (Wilson), and the chance level (25% with 4 methods). If the CI's lower bound is above chance, raters preferred that method more often than chance.
2. **Position check**: how often each position (A/B/C/D) was chosen. This should be close to chance; a large skew means raters favored a position.
3. **Per sample**: for each clip, how many raters chose each method.

To analyze in Python, use **File → Download → CSV** on the Ratings tab, then:

```python
import pandas as pd
df = pd.read_csv("ratings.csv")
df = df[df.note.isna()]
df.groupby("question").choice.value_counts(normalize=True)   # preference rate per method
pd.crosstab(df.sample_id, df.choice)                          # votes per clip
```

## Settings (config.js)

| setting | default | |
|---|---|---|
| `studyId` | `video-study-v1` | Change it for a new round; returning raters will then start fresh |
| `questions` | "Which video looks the most natural?" | Add more objects to ask several things per round, e.g. `{ id: "sync", text: "Which has the best lip sync?" }` |
| `randomizeOrder` | `true` | Each rater gets their own order of rounds, which stays the same if they reload |
| `randomizePositions` | `true` | Shuffle which method is A/B/C/D in every round |
| `requireFullWatch` | `true` | Answering unlocks only after every video has finished |
| `maxPlays` | `3` | How many times a round may be played (1 = no replay) |
| `playAudio` | `false` | `true` plays the sound of the left-most video only (when all versions share the soundtrack) |
| `askRaterId` | `true` | `false` = assign a random anonymous ID |
| `consent` | text | `""` = no consent checkbox |
| `completionCode` | `""` | Shown at the end, e.g. for Prolific or MTurk |

## Good to know

- **Saving is reliable.** Each answer is sent right away. If the connection drops, it is kept in the browser and re-sent later, and the Sheet ignores duplicates. A rater who closes the tab and returns with the same ID continues where they stopped.
- **The endpoint is open.** Anyone who finds the Sheet URL could submit rows. The script checks every value (for example, that the chosen method was actually shown in that round), but you should keep only rows from the participant IDs you handed out.
- **Best on a computer.** Four videos side by side are small on a phone. The page still works there, with a 2-column grid.
- Player controls and the right-click menu are disabled, so raters can't seek, change the speed, or play one video on its own.
