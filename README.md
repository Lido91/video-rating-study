# Video Rating Study

A static website for a video rating user study, built for GitHub Pages. Each rater:

1. Enters a participant ID (or gets one from the link, e.g. `?id=P017` or `?PROLIFIC_PID=...`) and gives consent.
2. Watches the videos one at a time, in a shuffled order that is different for each rater.
3. Rates each video on the scale you set (5-point ACR by default) after it has played to the end.

Ratings go straight into a Google Sheet that only you can see. Raters never see other people's scores.

```
index.html, style.css, app.js   the site
config.js                       your study settings (title, instructions, questions, Sheet URL)
videos/                         your video files
videos.js                       list of videos, generated by make_video_list.py
make_video_list.py              scans videos/ and writes videos.js
apps-script/Code.gs             Google Sheet backend (paste into Apps Script)
```

---

## 1. Add your videos

Copy your files into `videos/`. Subfolders are fine, e.g. `videos/methodA/clip01.mp4`. Then run:

```bash
python3 make_video_list.py
```

The script writes `videos.js` and warns you about:
- **Files over 100 MB.** GitHub rejects these. Keep the whole site under about 1 GB.
- **Codecs browsers can't play.** H.264 MP4, VP9 WebM and AV1 all work. HEVC/H.265 only works in Safari. ProRes, raw YUV and MPEG-4 Part 2 don't play in browsers. (This check needs `ffprobe`, which comes with ffmpeg.)

> **Quality studies:** if you have to convert files to H.264, remember that re-encoding changes quality. Use near-lossless settings such as `ffmpeg -i in.mov -c:v libx264 -crf 10 -preset slow -pix_fmt yuv420p out.mp4`, or encode all conditions from your source files the same way.

Each video's ID in the results is its path inside `videos/`, e.g. `methodA/clip01.mp4`.

## 2. Set up the Google Sheet

1. Create a new Google Sheet, e.g. "Video study results".
2. Open **Extensions → Apps Script**. Delete the sample code, paste in all of `apps-script/Code.gs`, and save.
3. Choose `setup` in the function dropdown and click **Run**. Approve the permissions prompt. This creates the **Ratings** and **Summary** tabs.
4. Click **Deploy → New deployment**. Under the gear icon choose **Web app**, then set:
   - Execute as: **Me**
   - Who has access: **Anyone**
5. Click **Deploy** and copy the **Web app URL** (it ends in `/exec`).
6. Paste the URL into `config.js`:
   ```js
   scriptUrl: "https://script.google.com/macros/s/AKfy.../exec",
   ```

To check it worked, open the web app URL in your browser. You should see `{"ok":true,"message":"Video rating endpoint is running."}`.

> **University Google accounts** (such as @ou.edu) sometimes don't offer the **Anyone** option. If you only see "Anyone within OU", raters outside OU will get an error. In that case, create the Sheet with a personal Gmail account instead.

> **If you edit Code.gs later**, go to **Deploy → Manage deployments**, click the pencil icon, set **Version → New version**, and click **Deploy**. The URL stays the same. Saving the file alone does not update the live web app.

## 3. Try it on your computer

```bash
python3 -m http.server 8000
```

Open http://localhost:8000/?id=test1&reset. Use `?reset` to forget this browser's progress so you can run through again. Delete your test rows from the Sheet before the real study starts.

If `scriptUrl` is empty, the site runs in **demo mode**. Ratings stay in the browser, and you can download them as CSV at the end. This is useful for piloting.

## 4. Publish on GitHub Pages

1. Create a new repository on GitHub, e.g. `video-study`. It must be **public** for free GitHub Pages.
2. Push this folder to it:
   ```bash
   git init
   git add .
   git commit -m "Video rating study"
   git branch -M main
   git remote add origin https://github.com/<your-username>/video-study.git
   git push -u origin main
   ```
3. On GitHub, go to **Settings → Pages**. Under **Source** choose **Deploy from a branch**, then **main** and **/ (root)**, and click Save.
4. After about a minute the site is live at `https://<your-username>.github.io/video-study/`.

Send each rater their own link: `https://<your-username>.github.io/video-study/?id=P001`.

> **Public repo means public videos.** Anyone can download the files in the repo. Ratings are not in the repo; they live only in your Sheet. Don't use Git LFS for the videos, because GitHub Pages doesn't serve LFS files.

## 5. Your data

**Ratings** tab: one row per rater × video × question. It is never overwritten.

| column | meaning |
|---|---|
| `timestamp` | when the rating reached the Sheet |
| `rater_id`, `session_id` | who rated it (the session ID changes if they start over on a new device) |
| `video_id`, `question`, `score` | what was rated and the score (1 = lowest) |
| `trial_index` | the video's position in this rater's order (for order-effect checks) |
| `plays` | how many times they played it |
| `stalls` | buffering interruptions during playback (should be 0, because clips are fully downloaded before playing) |
| `video_seconds` | clip duration |
| `response_ms` | time from the end of the video to clicking Next |
| `note` | `playback_error` if the video couldn't play on their device (score left blank) |
| `screen` | screen resolution in CSS pixels |

**Summary** tab: one row per video × question with `n`, `MOS`, `SD`, `CI95 (±)` (t-distribution), `min`, `max`, `unique_raters`, `playback_errors`, and how many raters gave each score (`#1` … `#5`). It is rebuilt every time a rating arrives; you can also use **Video ratings → Refresh summary** in the Sheet menu. Don't edit the Summary tab by hand, because your changes will be overwritten.

To analyze in Python, use **File → Download → CSV** on the Ratings tab, then:

```python
import pandas as pd
df = pd.read_csv("ratings.csv")
df[df.note.isna()].groupby(["video_id", "question"]).score.agg(["count", "mean", "std"])
```

## Settings (config.js)

| setting | default | |
|---|---|---|
| `studyId` | `video-study-v1` | Change it for a new round; returning raters will then start fresh |
| `questions` | 1 question, 5-point ACR | Add more objects to ask several questions per video. Each needs a unique `id` |
| `randomizeOrder` | `true` | Each rater gets their own shuffle, which stays the same if they reload |
| `requireFullWatch` | `true` | Rating unlocks only after the video ends |
| `maxPlays` | `2` | 1 = no replay |
| `askRaterId` | `true` | `false` = assign a random anonymous ID |
| `consent` | text | `""` = no consent checkbox |
| `completionCode` | `""` | Shown at the end, e.g. for Prolific or MTurk |

## Good to know

- **Saving is reliable.** Each rating is sent right away. If the connection drops, it is kept in the browser and re-sent later, and the Sheet ignores duplicates. A rater who closes the tab and returns with the same ID continues where they stopped.
- **The endpoint is open.** Anyone who finds the Sheet URL could submit rows. The script checks the format of every value, but you should keep only rows from the participant IDs you handed out.
- **Videos play at their own size** on a neutral gray background. They are only scaled down if larger than the page (or 70% of the screen height). Player controls and the right-click menu are disabled, so raters can't seek or change the speed.
